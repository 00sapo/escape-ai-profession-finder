Technical Notice

Statistical model and validation. Data bundle 2026-11-08. Notice 2026-11-09.

This notice describes how the site estimates the OECD AI Capability Gap of a declared activity profile. It gives the equations, the constants, the validation protocol, the held-out results, and the limits of the method. The notice is in English because it targets a technical audience. The site interface is available in seven languages.

Scope and data

The site works on the 879 O*NET occupations that carry an OECD score. The O*NET 31.0 text database supplies 2084 detailed work activities and 17712 occupation-activity links. The median occupation has 20 activities. The OECD 2026 workbook supplies the total gap index and the reversed normalized index. The OECD states that the total gap index has an effective maximum of 23. The reversed normalized index is e = 1 - g / 23. A low gap means high exposure.

The site ranks all 879 occupations. It does not restrict the candidate pool to the occupations that the user chose. The chosen occupations only build the initial activity list.

Evidence model

The user declares a performed set P and a denied set Q. Every other activity is missing. A missing activity is not an absent activity. It does not enter the likelihood.

Each declared activity carries a positive weight. The weight is the O*NET frequency from 1 to 5 when the caller supplies one. Otherwise the weight comes from the priority table described below. With smoothing ε = 0.02, the probability that occupation o contains activity d is:

po(d) = (1 − ε) aod + ε (1 − aod)

The weighted log-likelihood of the evidence under occupation o is:

ℓo = Σi ∈ P wi log po(i) + Σj ∈ Q vj log(1 − po(j))

The occupation score is the weighted geometric mean of the per-activity probabilities:

so = exp(ℓo / W),   W = Σi ∈ P wi + Σj ∈ Q vj

For non-empty evidence, so lies between 0.02 and 0.98. A single occupation that contains every performed activity scores 0.98. A single occupation that contains none of them scores 0.02.

Occupation score and candidate screening

The model ranks occupations by so. Ties use the priority score:

πo = Σr : dr ∈ P ∩ Ao 1 / (r + 1) − Σr : dr ∈ Q ∩ Ao 1 / (r + 1)

Here r is the 1-based position in the declared order.

The top 60 occupations by ℓo form the candidate set. The score and the similarity have the same order for a fixed total weight. The top 60 by score are therefore the top 60 by similarity.

Convex blend

The declared profile is a convex combination of occupation profiles. The weights θ are not negative and sum to one. For the candidate set C, the probability that the blend contains activity d is:

qd(θ) = ε + (1 − 2ε) Σo ∈ C θo aod

The blend maximizes the weighted log-likelihood:

F(θ) = Σi ∈ P wi log qi(θ) + Σj ∈ Q vj log(1 − qj(θ))

F is concave on the simplex. Its gradient is:

∂F / ∂θo = (1 − 2ε) [ Σi ∈ P wi aoi / qi − Σj ∈ Q vj aoj / (1 − qj) ]

Estimation algorithm

The model uses exponentiated gradient ascent. Let Go be the bracket in the gradient without the positive factor (1 − 2ε). The update is:

θo(t+1) = θo(t) exp(η Go(t) / ||G(t)||∞) / Zt

Zt normalizes the weights to one. The step is normalized by the largest gradient component. Dropping (1 − 2ε) rescales the step only. The page uses η = 1 and 320 iterations. The library default is η = 0.7. The update has no convergence test.

After the first optimization, the model sparsifies the support. It sorts the weights and keeps the smallest set K with at least 2 occupations, at most 10 occupations, and cumulative mass at least 0.9. If no such set exists, it keeps 10 occupations. It renormalizes the weights and runs 240 more updates on the trimmed support.

If P equals the full activity set of one occupation and Q is empty, the model sets the weight of that occupation to one and skips the optimization. This is a maximizer of F, because every performed activity is present at probability 1 − ε.

Estimate and uncertainty

The gap and exposure estimates are:

ĝ = Σo ∈ C θo go,   ê = Σo ∈ C θo eo

The effective support is 1 / Σ θo2. A value near one means that one occupation carries the blend. A larger value means that several occupations share the weight.

Uncertainty is the sample standard deviation of 24 bootstrap refits. Each refit draws max(1, round(0.8 |P|)) performed activities and max(0, round(0.8 |Q|)) denied activities with replacement. Each drawn activity carries its weight. The refit repeats the full estimation.

Priority weights

When the caller supplies no frequency map, the weight of a declared activity comes from the priority table. The table has 21 values. It is monotone non-increasing. It comes from O*NET importance ratings pooled over occupations and stretched linearly to the range 1 to 5. A declared activity at relative position q takes the linearly interpolated value τ(q).

The page passes the activity order and the priority table. It does not expose a frequency control. The model API accepts an optional frequency map. A supplied frequency from 1 to 5 replaces the priority weight. A missing entry in a supplied map gets weight one.

Title similarity

The ranking also uses the occupation titles. For every occupation, the app computes a fuzzy title similarity against the titles of the chosen occupations. The score is the maximum over the chosen titles:

to = maxr sim(titleo, titler)

Here titler is the title of a chosen occupation.

The matcher folds case and diacritics, splits on any non-letter or non-digit, and drops common words. It compares every token with the best token on the other side. A token match is the Dice coefficient of the character bigrams, with a prefix bonus. The score is symmetric and lies between 0 and 1. A typo keeps most of the score. An unrelated term scores zero.

The ranking similarity combines the activity similarity and the title similarity:

s*o = (1 − λ) so + λ to,   λ = 0.3

The title term changes the ranking and the displayed similarity. It does not change the blend weights, the support, or the gap estimate. The gap remains a function of the declared activities.

Validation

The harness splits the 879 occupations with an FNV-1a hash of the O*NET-SOC code. It tunes the two hyperparameters on 547 occupations. It reports on 332 held-out occupations.

For each occupation, the harness draws a uniform random subset of n activities from the occupation. It treats them as performed. It supplies no denied activities and no frequency map, so every weight is one. It fits the model and compares the estimated exposure with the OECD exposure of the same occupation.

With 15 percent of the sampled activities replaced by uniformly random activities, n = 20 gives MAE 0.0041, top-10 0.994, and rank-1 0.959.

The thresholds are MAE at most 0.05 and top-10 at least 0.70. The harness writes data/dist/validation_report.json and exits non-zero when a threshold is missed.

The activity harness passes no title similarity. A separate title check verifies the fuzzy matcher, the symmetry of the score, the typo case, and the ranking effect. It runs with npm run check:title.

What the validation does not show

  • The true occupation stays in the candidate pool. The protocol is transductive. It measures recovery, not generalization to unseen occupations.
  • The harness samples evidence from the same occupation. It does not use real user profiles.
  • The harness uses unit weights and no denied activities. It does not exercise the priority table, the frequency path, or the title similarity. Separate checks cover the priority table and the title similarity. The frequency path has no check.
  • The bootstrap resamples activities, not users. The standard deviation is a sensitivity measure, not a confidence interval.
  • The likelihood is not identifiable. Occupations with equal or nested activity sets give the same fit. The sparsification rule selects one maximizer.
  • The OECD index is not a causal prediction. A low gap does not prove that AI will replace the occupation.

Reproduce

python3 pipeline/build_dataset.py --check
npm run check:tuning
npm run validate
npm run check:priority
npm run check:title
npm run verify

npm run verify runs the data check, the tuning check, the i18n check, the translation check, the validation harness, the priority harness, the title check, and the Playwright tests.
